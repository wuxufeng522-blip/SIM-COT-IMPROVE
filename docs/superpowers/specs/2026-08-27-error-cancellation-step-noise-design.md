# GSM8K 错误抵消步骤噪声控制实验设计

日期：2026-08-27

状态：待用户审阅书面规格

硬件边界：单张 RTX 4060 Laptop GPU，8GB 显存

## 1. 研究问题

本实验验证：在最终答案监督始终正确且完全相同的条件下，SIM-CoT 的显式步骤监督若包含明显错误、但由第二个明显错误抵消并最终回到正确答案，是否会比长度和位置匹配的正确冗余监督造成更严重的答案准确率下降；若伤害成立，将错误步骤权重降低到 0.1 是否能够产生选择性恢复。

本实验不是自然教师噪声实验。所有错误抵消链和冗余链均为确定性规则生成的受控半合成数据，只允许用于机制和压力测试结论。

## 2. 核心因果变量

所有训练条件使用相同：

- 初始 checkpoint；
- 题目、正确最终答案及答案格式；
- 五个 latent 阶段和五个显式步骤槽位；
- 训练样本顺序、随机种子、优化器、更新次数及评估集；
- 总损失定义和第一阶段的步骤权重；
- 污染题 ID、污染位置和覆盖率嵌套关系。

第一阶段唯一计划改变的是辅助解码目标的语义内容：原始正确步骤、数学正确但冗余的步骤，或包含错误抵消链的步骤。

训练开始后，不同组的参数轨迹会分化，因此实际 `L_correct` 数值不要求继续相等；要求相等的是 `L_correct` 的输入构造、目标标签、实现和初始逐样本数值。

## 3. 数据来源与划分

- 训练来源：冻结的官方 GSM8K 训练源文件。
- 评估来源：冻结的官方 GSM8K test，共 1,319 题。
- 训练规模：512 个具有五个可解析计算步骤的唯一题目。
- 随机种子：`20260809`、`20260810`、`20260811`。
- 训练题与官方 test 必须保持题目 ID 零重叠。
- 25% 覆盖集合固定为 128 题；50% 覆盖集合固定为 256 题，且 128 题集合必须是 256 题集合的严格子集。
- 局部、广域、错误和冗余条件在同一覆盖率下必须使用相同题目 ID。

所有数据、调度和覆盖集合在读取实验结果前冻结并记录 SHA-256。冻结文件不得原地覆盖；修订必须创建新版本。

## 4. 严格输出格式

每条显式轨迹严格由五个计算步骤组成：

```text
<<表达式=结果>>
<<表达式=结果>>
<<表达式=结果>>
<<表达式=结果>>
<<表达式=结果>>
```

禁止：

- 自然语言解释或纠错提示；
- 为匹配长度而添加模板套话；
- 增删步骤；
- 修改最终答案字段；
- 将错误链得到的错误结果作为答案监督。

## 5. 三类轨迹构造

### 5.1 Clean

Clean 直接保留官方五个原始计算步骤，不重写、不拼接、不扩写。它是所有其他变体的父轨迹。

抽象示例：

```text
<<a+b=x>>
<<x*c=y>>
<<y-d=z>>
<<z+e=w>>
<<w/f=A>>
```

### 5.2 局部错误抵消

选择两个相邻步骤。第一步必须是独立计算器可证明的错误等式；第二步也必须是错误等式，但其声明结果必须与对应 Clean 步骤的状态相同。恢复后的剩余步骤与 Clean 逐字一致。

```text
<<a+b=x>>
<<x*c=y+delta>>
<<(y+delta)-d=z>>
<<z+e=w>>
<<w/f=A>>
```

标签类型固定为：

```text
CLEAN, DIRECT_FALSE, CANCEL_FALSE, CLEAN, CLEAN
```

实际位置可依据依赖图移动，但两个错误必须相邻，且污染与冗余匹配组使用相同位置。

### 5.3 大范围错误传播后抵消

第一个错误位于第 1 或第 2 步。中间步骤必须真实使用错误状态并将其传播；倒数第二个受影响步骤必须是独立计算器可证明的第二个错误等式，并将声明状态恢复为对应 Clean 状态。最后至少一个步骤与 Clean 逐字一致并输出正确答案。

```text
<<a+b=x+delta>>
<<(x+delta)*c=y_prime>>
<<y_prime-d=z_prime>>
<<z_prime+e=w>>
<<w/f=A>>
```

标签类型固定为：

```text
DIRECT_FALSE, ERROR_DESCENDANT, ERROR_DESCENDANT, CANCEL_FALSE, CLEAN
```

若无法同时证明传播依赖、第二个错误和最终恢复，则该题不得进入数据集。

### 5.4 匹配冗余

冗余变体在错误变体的相同步骤位置加入数学恒等冗余，但所有等式和中间状态必须正确。允许的中性操作仅包括：

```text
+0, -0, *1, /1, +(q-q)
```

使用 `q-q` 时，必须保证表达式可解析且单位语义不产生新的矛盾。若无法安全使用，则退回常数中性操作。冗余变体不得改变 Clean 的中间结果或依赖方向。

## 6. 构造验收门

每个五元组必须满足：

1. 三类轨迹均为五个合法的 `<<表达式=结果>>`。
2. 最终答案字段与 Clean 完全一致且经 GSM8K 精确匹配为正确。
3. `DIRECT_FALSE` 和 `CANCEL_FALSE` 由独立算术解析器判定为假。
4. `ERROR_DESCENDANT` 的输入必须引用前一错误状态，并能在依赖图上到达抵消步骤。
5. 抵消后状态必须与同位置 Clean 状态完全一致。
6. 抵消后的剩余步骤必须与 Clean 逐字一致。
7. 冗余变体的每个等式均由独立算术解析器判定为真。
8. Clean 永远不得为满足长度门而修改。
9. 错误和冗余变体的总辅助 token 数必须分别处于 Clean 的 90% 至 110%。
10. 错误变体与其冗余匹配变体的总辅助 token 数差异不得超过 5%。
11. 不满足长度条件的候选直接剔除，不允许填充说明文字。
12. 对冻结样本进行分层人工语义审计，检查错误显著性、传播、抵消、冗余正确性和最终答案。

## 7. 损失定义

所有第一阶段训练组使用：

```text
L_total = L_correct + lambda * L_step
lambda = 1.0
```

为排除目标长度导致的梯度剂量差异，步骤损失固定为逐步骤、逐有效 token 归一化：

```text
L_step = mean_i(mean_t(CE(i, t))), i = 1..5
```

第一阶段所有五个步骤的权重均为 `1.0`，包括已知错误步骤。答案分支不接收变体显式步骤文本；变体只改变辅助解码目标。

正式训练前必须在相同初始参数和相同题目上验证：

- 各变体 `L_correct` 逐样本完全相同；
- `lambda=0` 时各变体总梯度和参数更新完全相同；
- 步骤目标变化只作用于辅助损失路径。

## 8. 第一阶段训练矩阵

| 编号 | 条件 | 覆盖率 |
|---|---|---:|
| C | Clean | 0% |
| RL25 | 冗余-局部 | 25% |
| RL50 | 冗余-局部 | 50% |
| EL25 | 错误抵消-局部 | 25% |
| EL50 | 错误抵消-局部 | 50% |
| RW25 | 冗余-大范围 | 25% |
| RW50 | 冗余-大范围 | 50% |
| EW25 | 错误抵消-大范围 | 25% |
| EW50 | 错误抵消-大范围 | 50% |

九个条件各运行三个种子，共 27 次训练和 27 次官方 test 评估。

冻结训练参数：

- 512 个训练样本；
- 64 个优化器更新；
- 梯度累积 8；
- 学习率 `1e-4`；
- AdamW、weight decay `0.01`；
- 最大梯度范数 `1.0`；
- `latent_stage=5`、`c_thought=2`；
- BF16；
- 相同生成长度与 GSM8K 精确匹配评估器；
- 峰值 reserved 显存上限 `7.4GB`。

## 9. Clean 有效性门

在任何继续训练前，先对原始起点 checkpoint 在官方 test 上评估一次，记为 `Acc0`。随后训练和评估三个 Clean 种子。

Clean 门要求：

```text
mean(Acc(C)) >= Acc0 - 2.0 pp
min_seed(Acc(C)) >= Acc0 - 5.0 pp
```

若失败，流水线必须在所有冗余和错误条件前停止。不得修改阈值、Clean 数据或训练参数后跨配置续跑。

## 10. 第一阶段统计判定

预先指定主比较：

```text
H_primary = Acc(RW50) - Acc(EW50)
```

次要比较：

```text
H_local25 = Acc(RL25) - Acc(EL25)
H_local50 = Acc(RL50) - Acc(EL50)
H_wide25  = Acc(RW25) - Acc(EW25)
```

同时报告：

```text
redundancy_overhead = Acc(C) - Acc(R*)
total_error_harm    = Acc(C) - Acc(E*)
```

每个比较必须报告三个种子的原始准确率、均值、标准差、逐题配对差异和分层配对 bootstrap 95% 区间。

“存在可检测伤害”要求主比较同时满足：

- 三种子平均伤害至少 `2.0 pp`；
- 三个种子的伤害方向一致；
- 分层配对 bootstrap 95% 区间下界大于 `0`。

“严重伤害”额外要求三种子平均伤害至少 `5.0 pp`。只有达到该门槛，报告才能使用“严重影响”表述。

若主伤害门失败，第二阶段不启动，并报告“在受控错误抵消压力下未观察到可检测的增量语义伤害”。

## 11. 第二阶段：0.1 加权

仅在主伤害门通过后启动。第一步只运行大范围 50% 主条件的两个新增加权组：

| 条件 | 目标 | 权重 |
|---|---|---|
| EW50-w01 | 错误抵消 | `DIRECT_FALSE`、`ERROR_DESCENDANT`、`CANCEL_FALSE` 为 0.1；其余为 1.0 |
| RW50-w01 | 匹配冗余 | 与 EW50 相同位置为 0.1；其余为 1.0 |

等权 EW50 和 RW50 直接复用第一阶段冻结结果。

指标定义：

```text
R_error      = Acc(EW50-w01) - Acc(EW50-equal)
R_redundant  = Acc(RW50-w01) - Acc(RW50-equal)
R_selective  = R_error - R_redundant
F_recovery   = R_selective / H_primary
```

加权有效必须同时满足：

- `R_selective >= 1.5 pp`；
- 三种子的选择性恢复方向一致；
- 分层配对 bootstrap 95% 区间下界大于 `0`；
- `F_recovery >= 0.50`。

若通过，才扩展至大范围 25%、局部 50% 和局部 25%；每个扩展条件必须成对运行错误 0.1 组和对应冗余 0.1 组。若未通过，停止扩展，不得将原始恢复解释为选择性噪声加权收益。

## 12. 工程验证与安全续跑

正式流水线依次执行：

1. 数据解析器单元测试；
2. 五元组构造和算术复算；
3. 人工语义审计；
4. manifest、覆盖集合和训练 schedule 冻结；
5. `L_correct` 与 `lambda=0` 等价性审计；
6. 两更新 sanity gate；
7. 最长样本显存门；
8. 原始 checkpoint 官方 test 评估；
9. 三种子 Clean 门；
10. 第一阶段 24 个非 Clean 训练臂与全部评估；
11. 第一阶段分析；
12. 条件式第二阶段；
13. 最终报告。

每个训练和评估臂必须有独立目录、checkpoint 哈希和原子状态文件。恢复时只允许在同一配置、同一 seed、同一 arm 内从完整状态继续；禁止跨条件加载 checkpoint，禁止覆盖原始预测和生成记录。

显存超过 `7.4GB`、非有限损失、哈希变化、格式失败、答案不一致或门控失败时立即停止。工程性恢复不得修改科学参数。

## 13. 报告边界

最终报告必须明确区分：

- Clean 有效性；
- 冗余信息开销；
- 错误语义的增量伤害；
- 局部与广域传播差异；
- 25% 与 50% 剂量差异；
- 原始 0.1 恢复和扣除冗余掩码效应后的选择性净恢复。

无论结果如何，不得将本实验描述为自然教师错误率或真实教师噪声分布。其可支持的最强结论仅限于受控错误抵消监督是否会伤害 SIM-CoT，以及 oracle 式步骤降权是否能在该压力条件下选择性恢复性能。
