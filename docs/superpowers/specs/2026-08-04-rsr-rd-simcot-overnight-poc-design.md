# RSR-RD Weighted SIM-CoT 一晚概念验证设计

- 日期：2026-08-04
- 状态：设计已确认，尚未实施
- 目标硬件：NVIDIA GeForce RTX 4060 Laptop GPU，8 GB 显存
- 时间预算：8–10 小时

## 1. 目标与结论边界

本实验验证 RSR-RD 步骤权重能否在受控环境中被稳定计算、接入 SIM-CoT 步骤损失，并降低受污染推理步骤对训练的影响。

本轮不追求论文级 benchmark 结果，不进行多随机种子显著性检验，不声称在 GSM8K 或 MATH500 上取得性能提升。单次运行只能形成两类结论：

1. **工程可行**：权重计算与两组训练均稳定完成，且权重能够区分干净和污染步骤。
2. **初步有效**：在工程可行的基础上，加权组不降低答案准确率，并改善干净步骤的恢复质量。

## 2. 实验架构

整体数据流为：

`受控算术数据生成 -> Student 预热 -> 冻结评分模型 -> 离线计算 RSR/RD -> 等权与加权两组训练 -> 干净测试集评测`

实验使用一个预热 checkpoint 作为共同起点。等权组与加权组必须使用相同的数据、样本顺序、随机种子、优化器参数、训练步数和显存降级设置，唯一差异是步骤权重。

## 3. 数据设计

### 3.1 数据规模

- 训练集：1,200 条
- 验证集：200 条
- 测试集：200 条
- 数据生成随机种子：20260804

每条样本包含：

- 问题 `q`
- 2–4 个显式推理步骤 `s_1, ..., s_K`
- 与推理步骤分离的最终正确答案 `a`

算术生成器只产生可自动验证的整数运算，避免除零、非整数中间结果和超过预设数值范围的中间值。数据划分后再进行污染，确保同一基础题目不会跨集合泄漏。

### 3.2 训练监督污染

训练集中随机选取 20% 的样本，并在每个被选样本中污染恰好一个非答案步骤。污染类型等概率采样：

1. 数值篡改：修改中间运算结果但保留表面格式。
2. 无关步骤：替换为与当前问题无关但语法合理的算术步骤。
3. 重复步骤：复制一个已有步骤到错误位置。

最终答案始终使用正确标签。验证集和测试集完全干净。删除步骤不在本轮使用，因为它会改变 latent 与显式步骤的一一对应关系。

## 4. 模型与训练组件

### 4.1 模型

- 基础 Student：GPT-2 Small（约 124M 参数）
- 辅助步骤解码器：GPT-2 Small 结构，使用相同 tokenizer，并共享 token embedding
- 最大 latent 步数：4
- 每个有效显式步骤对应一个 latent；不足 4 步的样本使用 mask，不对 padding 计算损失

### 4.2 Student 预热

先在干净训练数据上进行约 400 个显式 CoT 更新步骤，使 Student 获得基础算术和答案预测能力。预热完成后保存 checkpoint，并复制出一个冻结评分模型。两条 SIM-CoT 训练分支都从同一预热 checkpoint 初始化。

### 4.3 冻结离线评分

评分模型在权重生成期间保持冻结。所有 RSR、RD 和最终权重预先计算并写入训练数据；训练期间不更新权重、不让梯度流入评分过程。这避免在线重复 forward pass 的高开销，也防止 Student 通过改变评分信号来投机优化。

## 5. 步骤权重

### 5.1 步骤级 RSR

对步骤 `t` 中的每个 token，在问题、此前步骤以及当前步骤 token 前缀的条件下计算 Student logits：

$$
\mathrm{RSR}_t =
\frac{\sum_j \min(\mathrm{Rank}(y_{t,j}), 100)}
{\sum_j \mathrm{Surprisal}(y_{t,j})}.
$$

Rank 无需全量排序，可通过统计 logits 中严格高于目标 token logit 的元素数量获得。原论文中的低 RSR 表示轨迹具有较好的“信息性—对齐性”平衡；它不是步骤正确率，不能直接当成越低越可靠的单调信号。

### 5.2 增量式步骤 RD

原始 MoRSD 的 RD 是完整 rationale 指标。本实验将其改为步骤的边际贡献：

$$
\mathrm{RD}_t = \exp\left(
\mathrm{NLL}(a\mid q,s_{\le t}) -
\mathrm{NLL}(a\mid q,s_{<t})
\right).
$$

答案 NLL 在相同答案 token 上取平均，因此两项可比较。RD 小于 1 表示加入该步骤后正确答案更容易预测；RD 越低越好。最终答案不写入步骤文本，以避免答案泄漏。

### 5.3 稳健变换与归一化

在整个训练集上分别对 `log(RSR)` 和 `log(RD)` 做 median/MAD 标准化：

$$
z(x)=\frac{x-\mathrm{median}(x)}{1.4826\,\mathrm{MAD}(x)+10^{-6}}.
$$

由于本实验面对的是受污染短步骤，先把异常低 RSR 视为低尾部异常，而不奖励高 RSR。联合分数和样本内归一化权重为：

$$
p_t^{\mathrm{RSR}}=\max(0,-z(\log \mathrm{RSR}_t)),
$$

$$
u_t=-0.5p_t^{\mathrm{RSR}}-0.5z(\log \mathrm{RD}_t),
$$

$$
w_t=\frac{K\exp(\mathrm{clip}(u_t,-2,2))}
{\sum_j\exp(\mathrm{clip}(u_j,-2,2))}.
$$

每个样本的有效步骤权重均值严格为 1。MAD 接近零时，将对应标准化分母下限固定为 `1e-6`；如果仍出现非有限值，评分阶段失败并停止，不进入训练。

## 6. 训练目标与公平对照

每个步骤损失先在该步骤的有效 token 上取平均，避免长步骤天然获得更大监督强度：

$$
L = L_{\mathrm{answer}} +
\lambda\frac{1}{K}\sum_t w_t L_{\mathrm{step},t},
\qquad \lambda=1.
$$

两条训练分支为：

- 等权组：所有有效步骤 `w_t = 1`
- 加权组：使用冻结离线计算的 RSR-RD 权重

共同训练设置：

- 训练随机种子：0
- 每组最多 800 个更新步骤
- FP16
- micro batch size：1
- 梯度累积：8
- AdamW，学习率 `1e-4`，weight decay `0.01`
- 梯度裁剪：1.0
- 梯度检查点开启
- 问题最大长度：96 tokens
- 单个推理步骤最大长度：48 tokens
- 最终答案最大长度：24 tokens
- 每 200 步保存 checkpoint
- Windows DataLoader worker 数：0

## 7. 8 GB 显存与失败处理

正式训练前运行 20-step preflight，记录峰值显存、loss 有限性、checkpoint 保存和恢复能力。只有 CUDA 峰值保留显存不超过 7.4 GB 才进入整夜训练，以便给桌面显示和临时张量留出余量。

如果发生 OOM，两组必须应用完全相同的降级方案并从共同 checkpoint 重新开始：

1. 先将问题、单步骤和答案最大长度分别缩短到 64、32 和 16 tokens。
2. 若仍 OOM，冻结 12 层辅助解码器中的底部 8 层，只训练顶部 4 层、基础 Student 和输出层。
3. 若仍无法完成 20-step preflight，则停止端到端实验，只报告环境阻塞，不把权重统计冒充训练结果。

任一训练分支出现非有限 loss、损坏 checkpoint 或无法恢复时，两组对比无效。不得只保留成功分支。

GPU 温度和显存使用在运行期间记录。总运行时间达到 10 小时时执行受控停止，保存最近的有效 checkpoint 和日志。

## 8. 评测

测试集保持完全干净，因为本实验评估的是训练时监督噪声，而非测试时 CoT 输入噪声。

### 8.1 权重质量

- 所有有效权重均有限
- 每个样本内权重均值为 1
- 污染步骤的平均权重低于其匹配干净步骤
- 以 `-w_t` 检测污染步骤的 ROC-AUC
- 分别记录 RSR-only、RD-only 和联合权重的离线区分能力，但不增加训练分支

### 8.2 模型质量

- 最终答案 Exact Match
- 干净步骤 token NLL/PPL
- 辅助解码器 teacher-forced token accuracy
- 完整步骤 sequence exact match
- latent 间平均成对 L2 距离，用于检查表示坍缩

### 8.3 运行质量

- 峰值 GPU 显存
- 总训练时间
- 每秒更新步数和样本数
- 最终完成的有效更新步数

## 9. 预注册成功标准

### 9.1 工程可行

必须同时满足：

1. 等权组和加权组均完成预定训练或同时因 10 小时硬停止而完成相同更新步数。
2. 无 OOM、非有限 loss 或 checkpoint 损坏。
3. 权重均有限且样本内均值为 1。
4. 污染步骤平均权重低于干净步骤。
5. 污染步骤检测 ROC-AUC 不低于 0.65。

### 9.2 初步有效

在满足工程可行的基础上，还必须满足：

1. 加权组测试集答案 Exact Match 不低于等权组。
2. 加权组干净步骤 token NLL 相对等权组至少降低 3%。

未满足“初步有效”不等于工程失败，必须如实报告为“权重与训练可运行，但本轮没有观察到预注册的质量收益”。

## 12. 评分门槛触发的探索性修订（2026-08-04）

首次正式冻结评分严格按原式
`u=-0.5z(log RSR)-0.5z(log RD)` 执行。结果为：联合污染检测 AUC `0.3505`、污染步骤平均权重 `1.2990`、干净步骤平均权重 `0.9784`，未通过第 9.1 节门槛，因此没有据此启动双分支训练。

分量审计显示，低 RSR 对污染步骤具有强区分力（AUC `0.9039`），高 RD 的区分力为 `0.6148`；这说明在本短步骤/合成污染设置中，极低 RSR 主要反映异常高 surprisal，而不是可靠的“优质信息性”。将 rank clipping 从 `100` 审计到 `50,257` 后方向仍未恢复，排除了 clipping 饱和作为主要原因。

因此采用第 5.3 节的低尾异常修订。该式不把高 RSR 当成奖励，只阻止异常低 RSR 获得无限偏好；RD 的方向保持不变。使用同一冻结分数进行探索性复算得到联合 AUC `0.7588`、污染步骤平均权重 `0.6796`、干净步骤平均权重 `1.0231`。由于修订参考了本轮污染标签，这些权重统计只作为概念验证的开发集诊断，不能作为独立确认性证据；最终模型效果仍在未参与调权的干净测试集上比较。
