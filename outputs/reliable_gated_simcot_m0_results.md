# M0 实验结果：官方 SIM-CoT 复现与 RTX 4060 单卡预检

日期：2026-08-05

硬件：NVIDIA GeForce RTX 4060 Laptop GPU，8188 MiB
勘误后的结论：**R001–R003 官方 checkpoint 数值复现 PASS；R004–R005 的旧训练预检因 `####` 步骤解析问题被降级，当前不允许进入 R010–R012 正式短预算训练。**

## 官方 checkpoint 四任务复现

| 任务 | 样本数 | 官方报告 | 本地复现 | 差值 | 判定 |
| --- | ---: | ---: | ---: | ---: | --- |
| GSM8K-Aug | 1319 | 44.8% | 44.43%（586） | -0.37 pp | PASS |
| GSM-Hard | 1319 | 9.3% | 9.48%（125） | +0.18 pp | PASS |
| MultiArith | 600 | 90.8% | 89.83%（539） | -0.97 pp | PASS，接近下界 |
| SVAMP | 1000 | 40.7% | 40.60%（406） | -0.10 pp | PASS |

四个任务都使用数据集答案字段作为真值；OOD 数值题使用发布版 `CODI/test.py` 的最后数值抽取规则。逐题预测均已保存。

## 单卡训练与恢复预检

- 旧 R004：BF16、batch 1、梯度累积 8、20 次更新，峰值 reserved 显存 5.52 GB；只能证明该实现的显存路径曾运行，不能再证明训练数据语义与官方完全一致。
- 旧 R005：checkpoint 保存/重载与继续更新在旧解析下成功，同样只保留为工程证据。
- 发现原因：训练文本用 `####` 分隔答案；旧适配器按最后一个 `##` 切分，给每条轨迹添加了伪 `##` 步骤。官方 `preprocessing/gsm_icot.py` 使用第一个与最后一个字段，现已严格对齐。
- 修正版 R004-v2：第一次完成 15/20 次有限更新后进程无 traceback 退出；第二次在首步前同样退出。按两次调试上限停止。R005-v2 未启动。
- 结论：RTX 4060 8GB 的显存可行性仍有旧运行支持，但“修正格式后的完整 20-step + reload”门槛尚未通过。

## 必须保留的审计结论

1. 早期规格把官方表中的 `12.2` 误读成 GSM-Hard 正确率；它实际是平均生成 token 数。正确 OOD 目标是 9.3% / 90.8% / 40.7%，规格已勘误。
2. 作者引用的私有格式化 OOD JSON 未发布。MultiArith 合并公开的 180 test 与 420 train 才对应论文 600 题主表；只跑 test 得到的 92.78% 不可直接和 90.8% 比。
3. 发布版 `Coconut/run.py` 导入但没有调用辅助步骤监督数据函数。R004/R005 按论文意图启用该路径；正式实验必须把它记为官方实现差异。
4. 官方入口依赖 NCCL/DDP/FSDP，Windows 单卡采用兼容 adapter；官方模型类、tokenizer、latent 构造、checkpoint 和答案规则均保留，并由四任务数值反向核验。
5. 截至 2026-08-06，33 个单元测试全部通过；pytest cache 权限警告不影响结果。

M0 当前只证明官方 checkpoint 的四任务评测复现可信；训练预检尚不完整，且尚未证明可靠性加权方法有效。R010/R011 已停止，转入停止规则允许的自然噪声检测可行性审计。
